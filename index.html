IMPORTANT DISTINCTION

Unsafe is not the same as deadlocked

The Banker’s Algorithm checks whether a state can guarantee a safe completion order. Deadlock detection separately checks processes that cannot complete under the currently allocated resources and outstanding requests.

iDo not label an unsafe state as confirmed deadlock. Keep avoidance and detection as separate functions.

DECISION RULE

Three checks before granting

01
Request ≤ Need

The process cannot request more than its declared remaining demand.

02
Request ≤ Available

If resources are unavailable, the process must wait. This is not automatically invalid.

03
Resulting state is safe

Temporarily allocate, run the safety algorithm, then commit or roll back.
